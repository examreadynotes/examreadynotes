💳 Custom QR Routing

Assign a custom UPI QR to specific students by email. When they check out, they see your custom QR instead of the default one. Everyone else still sees the default UPI.

⚙️ One-time Supabase Setup — run this SQL once
CREATE TABLE IF NOT EXISTS payment_qr_routes (
  id        bigint generated always as identity primary key,
  buyer_email text unique not null,
  upi_id      text not null,
  upi_name    text default 'Exam Ready Notes',
  label       text,
  active      boolean default true,
  created_at  timestamptz default now()
);

ALTER TABLE payment_qr_routes ENABLE ROW LEVEL SECURITY;

-- Admin: full access
CREATE POLICY "Admin full access"
  ON payment_qr_routes FOR ALL USING (true);

-- Students: can only read their OWN active route (for checkout)
CREATE POLICY "Student read own active route"
  ON payment_qr_routes FOR SELECT
  USING (active = true AND buyer_email = auth.email());

⚙️ Setup — EmailJS (Free, 200 emails/month)

Order confirmation receipts are sent automatically via EmailJS. Follow these steps once:

  1. Create a free account at emailjs.com and connect your Gmail.
  2. Create an Email Template. Set Subject: Order Confirmation – {{order_id}}
  3. ⚠️ Easy to miss — this is the #1 cause of "recipients address is empty": in the template editor, open the "Settings" tab (next to "Content") and set the "To Email" field to exactly {{to_email}}. This field is separate from the Subject/Body and is blank by default — if it's empty or has your own email typed in instead of {{to_email}}, every send will fail with exactly that error, no matter what the code sends.
  4. In the template body, add: {{{html_body}}} (triple braces = raw HTML).
  5. Copy your Public Key (Account → API Keys), Service ID, and Template ID.
  6. Paste all three into EMAILJS_PUBLIC_KEY, EMAILJS_SERVICE_ID, EMAILJS_TEMPLATE_ID at the top of both index.html and admin.html.

🩺 Seeing "The recipients address is empty"?

This error comes directly from EmailJS's servers — it means your code's request arrived fine, but the template didn't know which address to send to. It is always caused by the template's "To Email" setting (step 3 above), never by a bug in this page. To fix it:

  1. Open your template on dashboard.emailjs.com
  2. Click the Settings tab at the top of the editor (not Content)
  3. Find "To Email" and type exactly: {{to_email}}
  4. Save the template, then click 🧪 Send Test below again

⚙️ One-time Supabase Setup (run once in SQL Editor)
Run this to verify the table exists and is readable
CREATE TABLE IF NOT EXISTS launch_timers ( id bigint generated always as identity primary key, title text not null, emoji text default '🚀', launch_at timestamptz not null, active boolean default true, created_at timestamptz default now() ); -- Optional: track who wants to be notified CREATE TABLE IF NOT EXISTS launch_notify_requests ( id bigint generated always as identity primary key, user_id uuid references auth.users(id), launch_id bigint references launch_timers(id), email text, created_at timestamptz default now(), unique(user_id, launch_id) ); -- RLS: admin can do everything, public can READ active timers (REQUIRED for website display) ALTER TABLE launch_timers ENABLE ROW LEVEL SECURITY; DROP POLICY IF EXISTS "Admin full access" ON launch_timers; DROP POLICY IF EXISTS "Public read" ON launch_timers; CREATE POLICY "Admin full access" ON launch_timers FOR ALL USING (true); CREATE POLICY "Public read" ON launch_timers FOR SELECT USING (active = true); ALTER TABLE launch_notify_requests ENABLE ROW LEVEL SECURITY; DROP POLICY IF EXISTS "Users manage own" ON launch_notify_requests; CREATE POLICY "Users manage own" ON launch_notify_requests FOR ALL USING (auth.uid() = user_id);
